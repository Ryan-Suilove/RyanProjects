# A同学 AI 助手

基于 Qwen2.5 微调的二次元风格 AI 聊天助手，结合 FAISS 向量检索与 Neo4j 知识图谱实现 RAG 增强问答。

## 项目简介

A同学是一个具有鲜明人格设定的 AI 助手：
- **人设定位**：精通二次元知识的废宅风 AI，语气幽默、颓废、中二
- **核心能力**：动漫知识问答、角色剧情解析、作品推荐
- **技术特色**：双路并行检索策略，结合向量检索与知识图谱

## 技术栈

| 组件 | 技术选型 |
|------|----------|
| 基座模型 | Qwen2.5 |
| 微调框架 | LlamaFactory (LoRA) |
| 模型量化 | Llama GGUF |
| 向量数据库 | FAISS |
| 知识图谱 | Neo4j |
| Embedding | shibing624/text2vec-base-chinese |
| 推理服务 | LM Studio |
| Web 界面 | Gradio |

## 快速开始

### 1. 环境准备

```bash
# 克隆项目
git clone https://github.com/Ryan-Suilove/RyanProjects.git
cd RyanProjects/D-chatbot

# 安装依赖
pip install -r requirements.txt
```

### 2. 启动推理服务

使用 LM Studio 加载量化后的 GGUF 模型，启动本地 API 服务（默认端口 1234）。

### 3. 启动 Neo4j（可选）

```bash
# Docker 启动 Neo4j
docker run -d \
  --name neo4j \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/12345678 \
  neo4j:latest
```

### 4. 构建 RAG 索引

```bash
cd D-chatbot/rag

# 构建 FAISS 向量索引
python build_index_v2.py

# 构建 Neo4j 知识图谱（需先启动 Neo4j）
python auto_graph_builder.py
```

### 5. 启动 Web 服务

```bash
python web_ui.py
```

访问 `http://127.0.0.1:7860` 即可与 A同学 对话。

## 训练数据构造

### 数据格式

采用 Alpaca 格式的 instruction/input/output 结构：

```json
{
  "instruction": "你是谁？",
  "input": "",
  "output": "我就是那个在石家庄摆烂的 A 同学啊...",
  "system": "你是一个叫A同学的，精通二次元知识的，自嘲废宅风的AI助手"
}
```

### 数据处理流程

```
原始聊天记录 → 数据清洗 → 上下文筛选 → 身份锚点注入 → 训练数据集
```

核心脚本：
- `scripts/data_washing.py` - 清洗无意义内容
- `scripts/data_construct.py` - 构造 Self-Instruct 语料

## 微调配置

使用 LlamaFactory 进行 LoRA 微调：

```yaml
# 示例配置
model_name: Qwen/Qwen2.5-7B-Instruct
finetuning_type: lora
lora_rank: 8
lora_alpha: 16
learning_rate: 5e-5
num_train_epochs: 3
batch_size: 4
```

## 模型量化

使用 llama.cpp 将微调后的模型转换为 GGUF 格式：

```bash
# 转换为 GGUF
python convert-hf-to-gguf.py ./output_model --outfile a_tongxue.gguf

# 量化 (可选 Q4_K_M, Q5_K_M, Q8_0 等)
./llama-quantize a_tongxue.gguf a_tongxue-q4_k_m.gguf Q4_K_M
```

## 🔍 深度分析：真实语料的“降维打击”

### 1. 废宅思路的因果链
普通 AI 的逻辑是：`接收问题 -> 检索事实 -> 输出方案`。
A-Bot 的逻辑是：`接收问题 -> 评估自身废柴程度 -> 输出带吐槽的事实`。
> **示例：** 面对“复旦搬迁石家庄”的虚构命题，普通 AI 只会分析经济；A-Bot 会以“穷苦咸鱼买不起房”的角度破防，这种**情绪反馈比知识输出更具真实感**。

### 2. 括号美学与心理描写
通过对真实语料的学习，模型掌握了二次元特有的“括号吐槽”。这不仅是符号的模仿，更是对**“内心活动与表面台词不对称性”**的精准捕捉，这是纯 Prompt 调教无法企及的细腻度。


## 💡 总结与展望

**实验证明：** 语料的真实分布（Distribution）决定了人格的上限。通过将真实社交语料与专业身份信息混合，A-Bot 成功跨越了“恐怖谷效应”，从一个工具人进化为了一个有血有肉、会“破防”的交互实体。

根据测试集原始标注（True/False）统计，各迭代版本的表现如下：

## 🔍 版本演进分析

### **v1 版本：基础 FAISS 向量检索**
* **表现：** 仅能处理简单的语义匹配。
* **痛点：** 纯向量检索在处理“声优-角色-番剧”这类三元组硬关系时，极易因 Embedding 空间距离接近而产生“张冠李戴”的幻觉。
* **Case：** 无法准确区分不同作品中同名或相近属性角色的细节。

### **v2 版本：Neo4j 双路并行检索 + 提示词优化**
* **改进：** 引入 Neo4j 知识图谱。系统通过图查询获取“确定性事实”，与向量检索的“语义灵活性”互补。
* **效果：** 准确率飙升至 **81.3%**。在“种崎敦美”与“悠木碧”的声优对比测试中，逻辑路径清晰，彻底解决了事实性错误。

### **v3 版本：MarkdownHeaderTextSplitter + 原始Query优化**
* **改进：** 弃用递归字符切分，改用 Markdown 标题层级切分；同时保留原始 Query 避免 LLM 改写导致专有名词丢失。
* **效果：** **准确率突破 90%**。有效解决了由于切片过碎导致的上下文断裂问题，确保召回的每一个 Chunk 都是完整的“知识单元”。

---

## 💡 技术结论与思考

### 1. **为什么 Neo4j 是二次元垂直域的解药？**
ACG 知识库具有高度的**关联性**（人物关系网、声优出演作）。
* **FAISS** 擅长召回“氛围感”：如“推荐一些像《迷宫饭》一样的番”。
* **Neo4j** 擅长打击“幻觉”：通过 `(Actor)-[:VOICED]->(Character)` 的硬逻辑，保证事实不翻车。

### 2. **切片策略的“结构化生存”**
使用 `MarkdownHeaderTextSplitter` 后，检索到的内容自带标题属性（如：# 角色介绍 - ## 莱欧斯），这为微调后的 Qwen2.5 提供了极佳的 Prompt 上下文，显著提升了生成答案的精准度（Precision）。

---

## 🛠 后续优化建议

1.  **多跳查询 (Multi-hop) 强化：** 针对“跨作共演”等复杂关系，进一步优化 Cypher 模板自动生成能力。
2.  **Rerank 插件化：** 在双路召回后引入重排序模型，过滤 v3 中残留的约 9% 的噪声。
3.  **多模态融合：** 结合项目二次元属性，后续可尝试集成图像召回功能。

---

**总结：** 实验证明，**“图谱事实 + 结构化切片”** 是构建高质量垂直领域 RAG 系统的核心基石。
